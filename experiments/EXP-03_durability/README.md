# EXP-03 durability (Member A)

HYPOTHESIS — not yet measured: with flush-at-commit=1, sync_binlog=1 and doublewrite ON, the 100 committed deposits survive a mysqld process crash and the open deposit rolls back. A process crash is not an OS/power failure: flush-at-commit=2 primarily risks loss on OS failure. Report actual settings, not just this expectation.

Prerequisites: private MySQL option file, Windows MySQL service, scratch rebuild permission; crash execution additionally requires an elevated interactive shell and explicit operator authorization. A crash affects the entire MySQL instance, including other databases: arrange an isolated maintenance window. The agent must NEVER run -Execute.

1. t+0: `powershell -NoProfile -File experiments/EXP-03_durability/setup.ps1` rebuilds scratch, commits 100 deposits of 3.00, captures checksums/counts/settings and opens a second native mysql process with one uncommitted +7 deposit. Its connection ID and client PID are recorded. The second session sleeps for 600 seconds then rolls back automatically.
2. t+10, a second PowerShell window: `powershell -NoProfile -File experiments/EXP-03_durability/kill_and_restart.ps1` prints only the actual taskkill PID and detected service restart command if uniquely identified. If multiple mysqld processes or services exist, it reports candidates and refuses to guess; supply -MysqldPid and -ServiceName only after verifying the target instance. It does not execute either command in default mode. Use a second window because an outer native PowerShell pipeline may wait for its background child; alternatively invoke setup.ps1 with `&` in the current PowerShell process.
3. MANUAL, within 600 seconds of setup: the operator may run the same script with `-Execute`, read the instance-wide warning above and type `CRASH MYSQL` in the elevated shell. Rebuild or rerun setup first if the sleeping session has expired. The script waits for a real reconnect and records timestamps, then calls verify.ps1.
4. Verification compares both table row counts/checksums to the saved baseline, asserts the unique uncommitted reference is absent and checks all six invariants. It attempts InnoDB crash-recovery messages in performance_schema.error_log, then .err fallback. ACL failure is labeled manual verification. Do not treat an ordinary reconnect as crash evidence.
5. For a dry-run session, run `powershell -NoProfile -File experiments/EXP-03_durability/teardown.ps1` to KILL only the script's own sleeping connection, roll back the open transaction and verify invariants. No server process is terminated.

Raw naming: evidence/raw/EXP-03/<timestamp>/{committed.txt,before.txt,uncommitted.stdout.txt,crash-dry-run.txt,after.txt,verification.txt,invariants.txt}. The background SQL/stdout contains version/time/connection ID. Capture screenshots with those META lines visible and OS wall clock if desired. Dumps and binary logs are not evidence artifacts. RESULTS.md distinguishes preparation/dry-run from an actual crash, whose outcome remains NOT YET RUN until the operator executes it.
