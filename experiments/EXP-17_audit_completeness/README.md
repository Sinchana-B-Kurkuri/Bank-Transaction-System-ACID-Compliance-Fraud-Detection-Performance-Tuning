# EXP-17 audit completeness (Member A)

Pre-run HYPOTHESIS (actual measurements are in RESULTS.md): each successful mutation has the exact audit events derived from its executed statement plan and the correct session actor. Guard-rejected DML creates zero audit rows. A DBA can disable audit triggers; D5 provides an honest coverage boundary, not a defense against privileged DDL.

AUTOMATED: `powershell -NoProfile -File experiments/EXP-17_audit_completeness/run_auto.ps1`. Scratch is rebuilt with seed plus lab accounts. Requires temporary CREATE USER/GRANT and trigger DDL privileges. Existing reserved users cause refusal; passwords are random in memory and passed only in each child MYSQL_PWD environment, never written to SQL files or arguments. setup.ps1 and mutations.ps1 are dot-sourced by the driver, teardown.ps1 runs in finally. No identity state with a password is saved.

Manual session sequence: t+0 administrator rebuilds scratch and starts setup.ps1 via the driver (keeping that PowerShell session alive). At t+10 the driver opens separate native teller/customer sessions, reads USER() and maps the exact strings. At t+20 each login opens an account, deposits, withdraws, transfers and receives a routed loan. Each operation's audit ID interval is checked separately; table/action expected counts come from single-leg/transfer/account/loan counts in the mutation plan. At t+30 the administrator runs the direct-DML assertions in tests/integration/05_exp17.sql (Loans INSERT/UPDATE/DELETE, Accounts +1 paired with a matching direct ledger deposit, rejected below-minimum UPDATE, audit UPDATE/DELETE). Raw DML fixtures roll back. At t+40 the administrator disables A audits, creates pre-watermark account/transaction/loan rows, observes zero new audit rows, reinstalls auditing and verifies D5/I4 plus all six invariants. All temporary users/maps are then removed.

The Accounts audit chain checks JSON old/new balance and status; Transactions snapshots match their rows; direct loan tests check all three action snapshots and session identity. EXPECTED versus actual per-statement table/action groups are in EV-EXP17-counts.md, and JSON samples with session users/actor IDs in EV-EXP17-json.txt. Version/time metadata comes from the raw experiment directory and server watermark records. For screenshots show NOW()/VERSION() and the TEST lines together. The six guards remain installed throughout the honest gap demo. Audit_Log guards stop UPDATE/DELETE (5013); DBA TRUNCATE/DROP bypass row triggers and are documented, not executed against the audit table.

Tests/integration/05_exp17.sql also joins the full regression without disabling any trigger or relying on persisted experiment state. It creates unique synthetic fixtures and leaves the banking ledger consistent after its raw-DML transaction rolls back. B source files and B triggers are never modified; if the existing toggle safety detects B's dependent fraud trigger it refuses, requiring B to handle its lifecycle.
